# 机场地面保障作业管理平台

面向航班保障、机位分配、廊桥靠接、摆渡车调度、行李装卸、航油加注、除冰作业与延误处置的一体化机场地面保障作业工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `airport-ground-ops:entries` 这一项，或调用 `resetModule(模块)`。

## 机务勤务放行链

勤务任务的放行是一条链，规则集中在 `frontend/src/api/line-release.ts`，
`local-service.ts` 命中 `line` 模块时整段委托过去：

- **逐级推进**：状态只能按 待执行 → 执行中 → 待放行 → 已放行 走，跳步一律挡回；
  已放行是终点，不允许回到执行中或任何其它状态。
- **检查单号唯一**：一个检查单号同一时刻只能挂在一条在执行（执行中/待放行）勤务上。
  开始勤务、提交放行时撞号一律挡回，提示里写明撞的是哪条任务（任务编号+状态）。
  待执行不算占用（先开工先得），已放行随单归档、号码释放。
- **空缺不放行**：检查单号空缺的任务不许提交放行、不许确认放行。
- **重复放行只生效一次**：已放行的任务再点确认放行，返回成功但状态不动、台账不动。

**放行状态与检查单号对不上时以哪份为准**：以状态链为准记「放行事实」，以检查单号为
「生效凭证」，两个要件缺一个都不算放行生效。依据是：状态链是系统按顺序写入的流转记录
（每步都校验过上一步和凭证，不可跳步、不可回退），比人工填写的字段可信；但放行是安全
关键结论，状态到了已放行而检查单号空缺时不能仅凭状态放行航班——就低处理，按未放行计，
任务标异常待人工核查。`isEffectiveRelease` 是这条判定的唯一实现。

**航班保障台账的放行待办**：航班保障页按航班号关联勤务任务，放行状态现场从勤务数据算
（同一份数据、同一条 `isEffectiveRelease` 判定），台账自己不存放行状态，两边永远读的
是一份。关联任务未全部有效放行的航班计入「放行待办」。

规则有单测兜底：`cd frontend && npm test`（`src/api/line-release.test.ts`）。
